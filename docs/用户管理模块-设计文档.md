# 用户管理模块 — 设计文档（v0.1）

> 依据：[docs/用户管理模块-需求文档.md](用户管理模块-需求文档.md)（已审核通过）。
> 开放问题按建议默认采纳：Q1 支持关键词搜索 / Q2 本期不做改角色与重置密码 / Q3 本期不做用户操作审计 / Q4 允许普通 ADMIN 屏蔽自己 / Q5 启用后需重新登录（S-04 语义）。
> 状态：**✅ 已实施并合入 main**（commit "feat: 用户管理模块"）。
> 实施修正：V4 内置规则优先级由设计稿的 65/70/75 调整为 **6/7/8** —— 必须小于"接口-查看 GET /api/** AUTHENTICATED(10)"，否则 GET /api/users 会先命中 AUTHENTICATED 规则导致 VIEWER 可查看用户列表（与"权限配置-查看 5"同模式）。

---

## 1. 总览与架构决策

| 决策 | 说明 |
|---|---|
| 模块归属 | **auth 域扩展**（账号管理天然属于认证域）：新增 `auth/controller/UserAdminController`、`auth/service/UserAdminService`、`auth/dto/UserAdminDtos`；**复用** `auth/entity/User` 与 `auth/mapper/UserMapper`（延续包结构分层） |
| 数据库 | **无表结构变更**：复用 `sys_user`（enabled / token_version 已存在）；仅新增 Flyway **V4** 权限规则迁移 |
| 权限 | 复用动态权限规则体系：V4 内置 3 条规则 `GET/POST/PUT /api/users/** → ADMIN`；VIEWER 与匿名默认拒绝（fail-closed） |
| 吊销联动 | 屏蔽/启用 = `enabled` 切换 + `token_version + 1` + 同步 `UserAuthStateCache`（复用 S-04，**旧 token 立即失效**） |
| 密码 | BCrypt（与现有一致）；**任何响应不含 passwordHash** |
| 前端 | 新增 `/users` 路由 + 菜单（仅 ADMIN 可见）+ **补全路由角色守卫**（顺带修复 VIEWER 可直达 `/permissions` 的既有缺口） |

## 2. API 契约

统一响应体 `{code, message, data}`；错误码 400/401/403/404/405/409 沿用现有 `GlobalExceptionHandler`。

### 2.1 用户列表 `GET /api/users`

| 参数 | 说明 |
|---|---|
| `keyword`（可选） | 用户名模糊匹配（大小写不敏感） |

响应 `data`：
```json
[
  { "id": 1, "username": "admin", "role": "ADMIN", "enabled": true,
    "createdAt": "2026-08-15T04:00:00Z", "updatedAt": "2026-08-15T04:00:00Z" }
]
```
按 `id` 升序。**无 passwordHash 字段**（DTO 不包含）。

### 2.2 新增用户 `POST /api/users`

请求：
```json
{ "username": "zhangsan", "password": "password123", "role": "VIEWER" }
```

| 校验 | 规则 | 失败码 |
|---|---|---|
| username | 非空、≤64 字符、不与现有用户重复 | 400 / 409 |
| password | ≥8 位 | 400 |
| role | 仅 `ADMIN` / `VIEWER` | 400 |

成功：201 语义（本系统统一 200 + data，与既有接口一致），返回新用户 `UserResponse`（enabled 默认 true）。并发重复创建 → 唯一约束兜底 409。

### 2.3 屏蔽 / 启用用户 `PUT /api/users/{id}/enabled`

请求：`{ "enabled": true | false }`（**必须显式给出**，空体/缺字段 → 400）

| 场景 | 行为 |
|---|---|
| 目标用户不存在 | 404 |
| 目标为 `admin` 且 `enabled=false` | 400「admin 为特殊用户，不允许屏蔽」 |
| 同状态操作 | 返回当前状态（不报错、不重复吊销） |
| 屏蔽 | `enabled=false` + `token_version+1` + 缓存同步 → 旧 token 立即 401 |
| 启用 | `enabled=true` + `token_version+1` + 缓存同步 → 需重新登录（Q5） |

响应：更新后的 `UserResponse`。

### 2.4 删除用户

**不提供** `DELETE /api/users/**`（访问返回 405；也不做软删除）。

### 3.2 V4 迁移（permission_rule 内置规则）

```sql
INSERT INTO permission_rule (name, http_method, path_pattern, roles, priority, enabled, builtin) VALUES
('用户管理-查看', 'GET',  '/api/users/**', 'ADMIN', 65, TRUE, TRUE),
('用户管理-新增', 'POST', '/api/users/**', 'ADMIN', 70, TRUE, TRUE),
('用户管理-屏蔽', 'PUT',  '/api/users/**', 'ADMIN', 75, TRUE, TRUE);
```
优先级置于路由规则（40–60）之后、"默认-登录即可"（999）之前；`guardAdminSelfAccess` 现有守卫不受影响（权限模块写端点仍可达）。

### 3.3 Mapper SQL（UserMapper.xml 新增）

```xml
<!-- 用户列表：可选关键词模糊搜索，按 id 升序 -->
<select id="selectByKeyword" resultType="com.gatewaydashboard.auth.entity.User">
    SELECT <include refid="BaseColumns"/> FROM sys_user
    <where>
        <if test="keyword != null and keyword != ''">
            LOWER(username) LIKE LOWER(CONCAT('%', #{keyword}, '%'))
        </if>
    </where>
    ORDER BY id ASC
</select>

<!-- 屏蔽/启用：enabled 切换 + 版本自增（吊销旧 token），乐观条件由 Service 判 0 行 -->
<update id="updateEnabledWithVersion">
    UPDATE sys_user SET enabled = #{enabled}, token_version = token_version + 1,
                        updated_at = #{updatedAt}
    WHERE id = #{id}
</update>
```

### 3.4 UserAdminService 核心逻辑

```
list(keyword)            → userMapper.selectByKeyword(keyword) → 转 UserResponse（去 hash）
create(request):
    校验 username/password/role（BusinessException.badRequest）
    if countByUsername > 0 → conflict("用户名已存在")
    entity = 组装（enabled=true, tokenVersion=0）
    try insert → 用户已存在可登录（登录时 UserAuthStateCache.update 自动同步）
    catch DuplicateKeyException → conflict（并发兜底）
setEnabled(id, enabled):
    user = selectById(id) ?: notFound
    if "admin".equals(username) && !enabled → badRequest("admin 为特殊用户，不允许屏蔽")
    if user.enabled == enabled → 直接返回（同状态短路，不吊销）
    updateEnabledWithVersion(user)（受影响行数 0 → conflict 兜底）
    userAuthStateCache.update(username, tokenVersion+1, enabled)   // 吊销立即生效
    return UserResponse（enabled/tokenVersion 已同步）
```

`updateByIdWithVersion` 不用于此处：屏蔽无需密码哈希等全字段更新，专用 SQL 更贴近"人工维护 SQL"的诉求。

### 3.5 异常与安全

- `@Valid` 校验 DTO（`@NotBlank`/`@Size(min=8)`/`@Pattern(ADMIN|VIEWER)`）
- `SecurityUtils.currentUsername()` 获取操作者（暂未使用，为后续审计预留）
- 接口幂等：同状态短路；不新增敏感信息泄漏面

## 4. 前端设计

### 4.1 路由与菜单

```ts
// router/index.ts 新增
{ path: '/users', name: 'users', component: () => import('@/views/UserManageView.vue'),
  meta: { title: '用户管理', requiresAdmin: true } }
// beforeEach 增加角色守卫（顺带修复 /permissions 无角色校验的既有缺口）
if (to.meta.requiresAdmin && !auth.isAdmin) return { name: 'routes' }
```

```html
<!-- App.vue 菜单（权限配置后） -->
<el-menu-item v-if="auth.isAdmin" index="/users">用户管理</el-menu-item>
```

### 4.2 UserManageView.vue

| 区块 | 说明 |
|---|---|
| 工具栏 | 新建用户按钮（ADMIN 专属，页面即 ADMIN 可见） |
| 列表 | el-table：用户名 / 角色（tag）/ 状态（启用/停用 tag）/ 创建时间 / 操作列 |
| 操作列 | 屏蔽/启用按钮；**admin 行屏蔽按钮禁用**（tooltip「特殊用户不可屏蔽」） |
| 新增对话框 | el-dialog + el-form：用户名（必填）、密码（必填 ≥8）、角色（el-select ADMIN/VIEWER）；提交失败提示由拦截器统一处理 |

### 4.3 API 层（api/userAdmin.ts）

```ts
list: (keyword?) => get<UserResponse[]>('/users', keyword ? { keyword } : undefined)
create: (data: CreateUserRequest) => post<UserResponse>('/users', data)
setEnabled: (id, enabled) => put<UserResponse>(`/users/${id}/enabled`, { enabled })
```
