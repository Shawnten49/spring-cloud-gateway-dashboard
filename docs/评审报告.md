## 1. 摘要

**项目定位**：Spring Cloud Gateway 管理后台（Java 21 / Spring Boot 3.5.16 / Spring Cloud 2025.0.x WebFlux + Vue 3 / Element Plus）。数据库为路由唯一真源，保存即生效（热刷新），带 JWT 认证、动态权限规则、操作审计与外部网关管理（gateway-demo）。

**总体结论（健康度 B-）**：**架构骨架与自证文档是强项，安全默认值与交付物是短板，测试不足**。六维评审共 **0 个 P0**，但默认配置下存在 **3 条 P1 级接管路径**（见下），Docker 交付物**大概率当前不可构建**（未实机构建验证）。这是一个架构与代码质量良好、文档高度自洽的学习/演示级项目——可以跑通全流程，但**直接按当前交付物上生产 = 被接管**。

**最需关注的前 5 项**（跨维去重后）：

| # | 问题 | 级别 | 涉及维度 |
|---|---|---|---|
| 1 | **默认值治理缺失**：JWT 默认密钥公开可伪造任意 ADMIN token；默认口令 admin123/viewer123 公开且印在登录页；compose 把 MySQL 3306 暴露到宿主机 + 公开口令（可直连 DB 绕过全部鉴权）；无 prod profile | **P1 ×4** | 安全 / 代码质量 / 交付物 |
| 2 | **阻塞式 JPA 全部压在 Netty 事件循环线程**：同进程内嵌网关架构下，管理 API 慢查询直接拖慢网关业务转发 | **P1** | 代码质量 / 架构 |
| 3 | **Docker 交付物不可构建风险**：前后端 Dockerfile 缺 `.dockerignore`，`COPY . .` 会用宿主 macOS 的 node_modules 覆盖容器内 Linux 依赖 | **P1**（未实机构建验证） | 交付物 |
| 4 | **外部网关链路可靠性**：内部 token 空即放行 + 默认 token 公开；轮询校验和 (COUNT,SUM(version)) 理论碰撞；markRefreshed 竞态——且该模块**零测试** | **P2 ×3 + 测试 P1** | 架构 / 测试 |
| 5 | **测试充分性不足**：架构评审确认的 7 类缺陷（含上述）**全部溜过测试网**；gateway-demo 整个模块无测试；前端除 51 行工具函数外零测试 | **P1 ×6** | 测试 |

**已实测确认的正面事实**（「起服抽查 API 行为」，H2/MySQL 双 profile）：保存即生效热刷新真实工作（创建后立即出现在生效路由）、并发乐观锁 409 正常、权限规则新增/删除即时生效、内置规则不可删、审计 5 类动作全落库（操作者/变更前后/IP）、401/403/405/409 全统一 JSON 无堆栈泄漏。**架构层面「数据库为真源」的设计是被验证过、可信的。**

## 3. 六维发现

### 3.1 架构与设计评审

**判断：骨架良好，忠于 ADR 决策，无 P0/P1。** 数据库唯一真源 + 自定义 `RouteDefinitionLocator` 忠实落地 ADR 0001/0002；保存即生效用 `afterCommit` 保证"先提交后刷新"（ADR 0003 时序正确）；权限 DB 化 + fail-closed + 自我保护与 ADR 0005 一致；外部网关"推送 + 5s 轮询校验和兜底"双通道设计合理、失败可自愈。包划分总体清晰（common/auth/audit 无反向依赖）。风险集中在 P2×10 + P3×18。

- **P2 要点**：内部接口空 token 放行（F15）；阻塞 JPA 在事件循环（F19，与代码质量 P1-01 同根，取 P1）；markRefreshed 竞态（F12）；校验和理论碰撞（F13）；create 并发 500 非 409（F8）；推送无超时（F11）；route↔config 包级环（F1）；双份平行 DbRouteDefinitionLocator（F4）；内嵌网关无外部变更兜底（F5）；状态页"生效路由"实为 DB 直读（F25）。
- **建议修复顺序**（子代理给出）：F15（一行语义）→ F19 → F12+F13 → F8 → F11 → F1/F4。
- 完整：`wayfinder/findings/architecture-review.md`（分支 `research/architecture-review`）。

### 3.2 代码质量与可维护性评审

**判断：质量中上（B+），无 P0。** 分层清晰、命名贴合 CONTEXT.md 领域词汇、record DTO 与实体分离（Assembler 集中转换）、Optional/乐观锁/统一异常出口规范、前端 strict TS + 薄 API 层。问题集中在四类：**WebFlux 事件循环上跑阻塞 JPA（架构性，P1）**、**多处静默吞异常/静默丢数据（P1/P2）**、**默认凭据与密钥（P1）**、**校验规则三层重复（P2）**。共 P1×4 / P2×8 / P3×20。

- **P1**：① 阻塞 JPA 压事件循环（多个 Controller + DbRouteDefinitionLocator + GatewayStatusService）；② 审计序列化失败静默返回 null（`RouteAssembler.java:98-104`，审计内容静默丢失且无日志）；③ 默认口令硬编码且登录页公开展示；④ 默认 JWT 密钥/内部 token 硬编码且默认 profile 即 dev。
- **P2**：setEnabled 裸 Map 静默停用路由；guard 只模拟 POST（自锁守卫不完整）；fire-and-forget 无 Disposable 管理；健康检查吞异常；校验规则三层重复（routeId 正则/httpMethod 白名单）；CORS 硬编码；DB 口令明文入库；审计截断产生非法 JSON（5000 常量两处重复）。
- **亮点**：包结构贴合领域、DTO/实体分离 + Assembler、`@Version` + `open-in-view:false` + Flyway、权限内存缓存 AtomicReference + 预编译 PathPattern、前端 strict TS。
- 完整：`wayfinder/findings/code-quality-review.md`（分支 `research/code-quality-review`）。

### 3.3 安全评审

**判断：安全基线总体合格，但「开箱即用」的默认配置存在 3 个 P1 级接管路径（全部属"默认值治理"），任一命中即完全控制网关配置面。** 认证授权运行时行为与设计一致（002 实测对照全部吻合）；已核实有效控制：无 SQL 注入面、BCrypt 存口令、fail-closed 默认拒绝、登录失败统一文案（无用户名枚举）、actuator 最小暴露、jjwt 标准实现无 alg:none 降级、前端无 v-html XSS 汇点、写面权限收敛（VIEWER 仅 GET + 自改密码）、Bearer+CSRF 关闭组合可接受。共 P1×3 / P2×4 / P3×11（S-13 原评 P3，经协调者交叉转发核查后**上调为 P2**）。

- **P1**：**S-01** JWT 默认密钥公开可离线伪造任意 ADMIN token（application.yml:27 + docker-compose.yml:31）；**S-02** 默认口令硬编码 + 登录页明文展示（SeedDataInitializer.java:34-41 + LoginView.vue:45-47）；**S-03** compose 暴露 MySQL 3306 + 公开口令（直连 DB 完全绕过应用鉴权，且改 route_config 5 秒内被外部网关轮询生效）。
- **P2**：**S-04** 无 token 吊销 + 角色固化 12h（改密/停用/降权后旧 token 仍有效，002 实测；威胁模型定性 P2：不可独立利用，但击穿账号生命周期补救路径）；**S-05** 内部接口空 token 放行 + 默认 token 公开 + 非恒定时间比较（与架构 F15 同根）；**S-06** 审计 IP 信任 X-Forwarded-For 可伪造（审计是 ADR 0003 唯一补偿控制，安全视角上调 P2，代码质量原评 P3）；**S-13（上调自 P3）** guard 只模拟 POST + update 无 builtin 保护——攻击面：ADMIN 建 `PUT /api/permission-rules/** → VIEWER` 规则（priority 无界，0/负数压过内置）→ 公开凭据的 VIEWER 获 PUT → update 任意规则**含内置**（`:70-81` 无 builtin 检查）→ 把内置路由写规则改 VIEWER/`*` → **VIEWER 获路由增删改（网关流量劫持/DoS）**；守卫的存在（ADR 0005 承诺）与实现不一致、006 确认测试盲区。
- **威胁模型**（谁攻击/怎么攻击/影响）：匿名访问者（默认口令/伪造 JWT/直连 DB）→ 完全接管；VIEWER → 信息读取/取证混淆；失陷会话 → 12h 持续越权窗口；运维误配（token 留空/3306 暴露）→ 内部接口公开。
- **建议修复优先级**：S-01/S-02/S-03（默认值治理，一个 PR）→ S-05（一行语义）→ **S-13（guard 覆盖全部写端点 + update 保护内置规则 + priority 加界）** → S-04 → S-06 → P3 按成本。
- 完整：`wayfinder/findings/security-review.md`（分支 `research/security-review`）。

### 4.2 P1（产品缺陷，4 组）

**P1-A 默认值治理缺失——部署即接管（安全 S-01/S-02/S-03 + 代码质量 P1-03/P1-04 + 交付物 P1-2）**
- 位置：`application.yml:27`（JWT 默认密钥）、`docker/docker-compose.yml:8-13,31`（MySQL 3306 全接口暴露 + 公开口令 + JWT 固定值）、`SeedDataInitializer.java:34-41`（admin123/viewer123）、`LoginView.vue:45-47`（登录页明文展示）、无 prod profile。
- 为什么：攻击者可用公开默认值离线伪造任意 ADMIN token、用默认口令直接登录、或直连 MySQL 绕过全部鉴权（外部网关 5s 轮询使改 route_config 立即生效）。
- 建议修法：生产 profile 启动强校验 JWT_SECRET 必填且非默认值；口令环境变量化/随机化 + 首登强制改密 + 删除登录页展示；compose 不发布 3306（或仅 127.0.0.1）+ secrets 注入；新增 `application-prod.yml`（敏感项无默认值）。

**P1-B 阻塞式 JPA 全部压在 Netty 事件循环线程（代码质量 P1-01 / 架构 F19，架构评 P2）**
- 位置：`RouteController.java:33-76`、`AuditController.java:24`、`PermissionRuleController.java:27-45`、`AuthController.java:27-41`、`RouteMetaController.java:23-30`、`DbRouteDefinitionLocator.java:17-20`、`GatewayStatusService.java:37-44`。
- 为什么：`Mono.just(阻塞调用)` 在 handler 求值时即跑 JDBC；**同进程内嵌网关架构（ADR 0002）下，管理 API 慢查询直接拖慢网关业务转发**。
- 建议修法：`Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())` 统一包裹（delete 的 doOnNext 改 flatMap）；长期可 R2DBC。

**P1-C 审计序列化失败静默返回 null（代码质量 P1-02 / 测试 P1-5 关联）**
- 位置：`RouteAssembler.java:98-104` → 审计 before/after 静默为 null 入库、无日志。
- 为什么：审计是 ADR 0003（无草稿、保存即生效）唯一追溯手段，静默丢失违背承诺。
- 建议修法：`log.error` + 显式占位串，或审计边界统一捕获。

**P1-D Docker 交付物不可构建风险（交付物 P1-1，未实机构建验证）**
- 位置：`frontend/Dockerfile:3-6`（缺 `.dockerignore`，`COPY . .` 覆盖 Linux node_modules）；`backend/Dockerfile` 同缺。
- 为什么：macOS 宿主构建大概率失败（darwin 平台二进制进 Linux 容器）。
- 建议修法：加 `.dockerignore` + 分层 COPY（package*.json → npm ci → src）；补 backend `.dockerignore`；在有机器的环境实跑 `docker compose up -d --build` 验证。

### 4.3 P2（产品缺陷，去重后 27 条）

**安全/信任边界**
1. 内部接口空 token 放行 + 默认 token 公开 + 非恒定时间比较（架构 F15 / 安全 S-05）— `gateway-demo/RouteRefreshController.java:67-74`、`RouteSyncProperties.java:11`。修：默认拒绝 + `MessageDigest.isEqual` + 强随机 token。
2. 无 token 吊销 + 角色固化 12h（安全 S-04）— `JwtAuthenticationFilter.java:26-37`、`JwtService.java:33`、`AuthService.java:41-50`。修：token_version/jti 吊销（或缩短有效期 + 文档化边界）。
3. 审计 IP 信任 X-Forwarded-For 可伪造（安全 S-06，安全视角上调）— `SecurityUtils.java:17-25`、`nginx.conf:10`。修：受信代理 X-Real-IP。
4. 自我保护 guard 只模拟 POST + 内置规则可被 update 改/禁用（代码质量 P2-02 / 安全 S-13 上调 P2 / 规范 P2-3）— `PermissionRuleService.java:33,149-162`、`:70-81`。攻击链：`PUT /api/permission-rules/** → VIEWER`（priority 0/负数）绕过守卫 → VIEWER 提权 update 内置规则 → 获路由写（网关流量劫持）。修：guard 改不变式列表（ADMIN 对权限模块全部写端点可达 + 路由写面最小角色=ADMIN）+ update 禁改内置规则 + priority 加界（0-999）+ 补 PUT/DELETE/`*`/提权链集成测试。

**路由/并发**
5. create 并发同 routeId → 500 非 409（架构 F8）— `RouteService.java:43-53`、`GlobalExceptionHandler.java:69-74`。修：捕获 `DataIntegrityViolationException` 映射 409。
6. markRefreshed 竞态（架构 F12）— `RouteSyncScheduler.java:40-64`。修：去掉 lastRefreshedChecksum 二次判断或加锁。
7. 轮询校验和 (COUNT,SUM(version)) 理论碰撞（架构 F13）— `RouteSyncScheduler.java:66-77`。修：单调 revision 水印。
8. setEnabled 裸 Map，畸形请求体静默停用路由（代码质量 P2-01）— `RouteController.java:64-71`。修：`@Valid` DTO。
9. delete 无乐观锁（架构 F9，P3）随 create/delete 并发缺口（架构 F20）— 软删除或显式版本校验（记录为已知边界可接受）。

**响应式/资源**
10. 推送 fire-and-forget 无超时/无生命周期（架构 F11 / 代码质量 P2-03）— `ExternalGatewayRefreshService.java:38-52`。修：`.timeout(3s)` + Disposable 管理 + 节流。
11. 健康检查吞异常（代码质量 P2-04）— `GatewayStatusService.java:41-43`。修：记日志 + 卸载到 boundedElastic。

**架构/模块**
12. route↔config 包级环（架构 F1）— 推送服务迁独立 integration 包。
13. 双份平行 DbRouteDefinitionLocator（架构 F4）— 抽共享模块/公共解析工具。

**配置/校验**

## 5. 结论与建议

### 5.1 总体评价

- **架构（A-）**：真源设计、热刷新时序、动态权限、双通道推送均验证可信；文档高度自洽（规范一致性"一致（高）"）。
- **代码质量（B+）**：分层与命名好、无 P0；阻塞 JPA 与静默吞异常是主要扣分点。
- **安全（默认值 C / 运行时 B+）**：运行时控制（fail-closed、统一 JSON、无注入、无 XSS 汇点）扎实；**默认配置即可被接管**是本项目上线前的第一道门槛。
- **测试（C）**：冒烟级；已确认缺陷无一被测试网捕获；gateway-demo 裸奔。
- **交付物（C）**：Docker 大概率不可构建（未验证）、无 prod profile；README 准确是亮点。

### 5.2 建议修复路线（若开启修复 effort——本 effort 明确只评审不改码）

1. **PR 1：默认值治理（建议合并为一次 PR）**——P1-A 全部：JWT_SECRET 启动强校验 + 口令环境变量化/随机化 + 删除登录页展示 + compose 去 3306 暴露/去字面凭据 + 新增 prod profile。同时修 S-05（空 token 默认拒绝，一行语义）。
2. **PR 2：响应式正确化**——P1-B：全部阻塞调用 `subscribeOn(boundedElastic)`（改动面小收益大）。
3. **PR 3：可靠性**——F12+F13（轮询兜底）、F8（409）、F11（推送超时）、P1-C（审计序列化）。
4. **PR 4：测试补强**——按测试充分性 P1 顺序：gateway-demo 切片测试 + 外部网关 mock 推送（含已确认缺陷的回归测试）→ 权限边界（暴露 guard 洞后修 guard）→ 改密 → 审计多动作；同步引入 jacoco/vitest coverage 门槛。
5. **PR 5：交付物**——.dockerignore + 分层 COPY 后**实机构建验证**；文档三处 P2 修订（SUM(version)、单实例边界、自我保护措辞）。
6. **长期**：Boot 3.5 已过 OSS（2026-06-30），规划升级 Boot 4 / SC 2025.1（注意 starter 改名）；多实例落点（内嵌网关兜底 + 刷新传播端口）。

### 5.3 后续建议

- 若"交付"指可运行 demo：修 P1-A 中的 Docker 构建 + 文档三处 P2 即可；若指可上线：P1 全项 + P2 中的安全/信任边界（1-4）为前置条件。
- 本 effort 的地图在此闭合；是否开启修复 effort 由你决定——若开启，建议以本报告的分级清单为 backlog 源头（默认值治理一个 PR 起手）。
