# 用户管理模块 — 需求文档（v0.1）

> 状态：**待审核**。本模块将新增"用户管理"能力：ADMIN 可新增用户、屏蔽/启用用户，不允许删除用户；`admin` 为特殊用户，不允许被屏蔽。
> 文档审核通过后，再出设计文档；设计通过后进入编码。

---

## 1. 背景与目标

系统当前仅有登录认证与预置账号（admin / viewer），**没有用户管理能力**：无法新增用户，无法屏蔽违规账号。本期新增用户管理模块，让 ADMIN 可以在界面上自助管理用户账号（增加 / 屏蔽 / 启用），同时通过两条硬性约束保障系统可用性与安全性：

- **不允许删除用户**（防止误删导致审计与关联数据不可追溯）；
- **`admin` 为特殊用户，不允许被屏蔽**（保证系统永远存在可用的管理员入口）。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 屏蔽 | 将用户 `enabled` 置为 false：该用户**无法再登录**，且**已签发的 token 立即失效**（复用现有 S-04 吊销机制） |
| 启用 | 将用户 `enabled` 置为 true：恢复登录能力 |
| 特殊用户 admin | 用户名固定为 `admin`（种子账号），系统级保护：**禁止屏蔽** |

## 3. 角色与权限

| 操作 | ADMIN | VIEWER |
|---|---|---|
| 查看用户列表 | ✅ | ❌（403） |
| 新增用户 | ✅ | ❌ |
| 屏蔽 / 启用用户 | ✅ | ❌ |
| 删除用户 | ❌（**接口不存在**） | ❌ |
| 屏蔽 `admin` | ❌（后端强制 400 拒绝） | ❌ |

- 权限通过现有**动态权限规则**（`permission_rule` 表）实现：新增 3 条内置规则（GET / POST / PUT `/api/users/**` → ADMIN），与现有"接口-查看 GET /api/** AUTHENTICATED"等规则按优先级匹配。
- 不新增角色类型（仍为 ADMIN / VIEWER 两种）。

## 4. 功能需求

### FR1 用户列表
- `GET /api/users`：返回全部用户，字段为 `id / username / role / enabled / createdAt / updatedAt`（**绝不返回 password_hash**）。
- 支持可选关键词过滤（按用户名模糊匹配，`keyword` 查询参数）。
- 列表按 `id` 升序；数据量小（管理后台账号级），本期不做分页。

### FR2 新增用户
- `POST /api/users`，请求体：`username`（非空、≤64 字符、不可与现有用户名重复）、`password`（≥8 位，与现有改密强度一致）、`role`（仅 ADMIN / VIEWER）。
- 新增用户 `enabled` 默认为 true；密码 BCrypt 加密存储（与现有一致）。
- 用户名重复 → 409；参数不合法 → 400；并发重复创建 → 409（唯一约束兜底）。
- 新用户创建后**立即可登录**。

### FR3 屏蔽 / 启用用户
- `PUT /api/users/{id}/enabled`，请求体：`{"enabled": true|false}`（必须显式给出，参照路由启停接口的强校验，空体返回 400）。
- 屏蔽效果：
  - 该用户无法再登录（现有登录校验返回"账号已停用"）；
  - 该用户**已签发的 token 立即失效**（`token_version + 1`，复用 S-04 吊销机制，无需等待过期）。
- 启用后用户可重新登录（签发新 token）。
- 同状态操作（已屏蔽再次屏蔽）视为无变化，直接返回当前状态（不报错、不重复吊销）。

### FR4 `admin` 特殊用户保护
- 对 `admin` 执行屏蔽 → 后端返回 400「admin 为特殊用户，不允许屏蔽」。
- `admin` 的启用（enabled=true）不受影响（其默认即启用）。
- 前端：admin 行不展示"屏蔽"操作（或置灰并提示）。

### FR5 不允许删除用户
- **不提供任何删除接口**（`DELETE /api/users/**` 不存在，访问返回 405）。
- 不做软删除、不做停用即删语义——被屏蔽的用户保留在列表中，可随时启用。

### FR6 前端
- 新增"用户管理"菜单/页面，仅 ADMIN 可见（路由守卫 + 后端权限双重控制）。
- 页面功能：用户列表（用户名/角色/状态/创建时间）、新增用户对话框（用户名/密码/角色，含 8 位密码与必填校验）、每行"屏蔽/启用"操作。
- `admin` 行：屏蔽按钮禁用（tooltip 说明"特殊用户不可屏蔽"）。
- 屏蔽/启用后列表即时刷新；新增成功后列表即时刷新。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 密码仅 BCrypt 存储；任何响应不含密码哈希；`/api/users/**` 全部接口默认拒绝（fail-closed），仅内置规则授予 ADMIN |
| 兼容 | 复用现有 JWT 吊销（S-04）、`UserAuthStateCache`、异常统一 JSON（400/403/404/405/409）、分页/校验模式；不改变现有登录/改密行为 |
| 数据 | 复用 `sys_user` 表，**无表结构变更**（enabled / token_version 字段已存在）；权限规则经 Flyway V4 迁移新增 |
| 边界 | 单实例语义不变；不新增第三方依赖 |

## 6. 明确不做（本期边界）

- ❌ 修改用户角色 / 重置其他用户密码（密码修改维持现状：本人经"修改密码"接口自助完成）
- ❌ 删除用户（含软删除）
- ❌ 用户操作审计（如需，列入后续版本；现有审计仅覆盖路由操作）
- ❌ 登录 IP 白名单 / 用户分组 / 批量导入

## 7. 验收标准

1. ADMIN 可新增用户（含角色选择）；新用户可用新密码登录成功
2. ADMIN 屏蔽某用户后：该用户登录返回 401；其已签发 token 访问受保护接口返回 401（吊销生效）
3. ADMIN 启用该用户后：可重新登录
4. 屏蔽 `admin` 返回 400；`admin` 行前端无可用屏蔽操作
5. `DELETE /api/users/**` 返回 405；VIEWER 访问 `/api/users/**` 全部返回 403
6. 用户名重复 409、密码 <8 位 400、空 enabled 体 400
7. 列表/详情响应中不存在 `passwordHash` 字段
8. 新增用户不破坏现有登录/改密/权限规则/路由管理功能（全量回归）
